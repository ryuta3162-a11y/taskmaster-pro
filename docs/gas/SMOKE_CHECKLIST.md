# 主要3経路スモークテスト（壊れ防止用）

改修・デプロイのあと、**利用者向けの挙動が変わっていないか**を短時間で確認するためのリストです。  
自動テストではなく、人が同じ手順で見る「検品リスト」です。

> コード整理（`src/lib/` / `src/ui/` への分割）後も、**見た目・動きは変えていない**前提です。本番反映後は下の A〜C を一度通すと安心です。

前提：テスト用の自分宛（または検証用アカウント）で実施。本番データを壊さないよう、内容は「確認用」と分かる短文にする。

---

## いつやるか

- `App.jsx` / `Code.gs` / `admin.html` のいずれかを本番反映したあと
- とくに **新規投稿・再投稿・リマインド** に触れた改修のあと

所要目安：10〜15分

---

## A. 新規投稿

1. ホーム → **新規投稿**
2. 依頼の種類・内容・期限・配信先を設定して送信
3. 確認
   - [ ] 通知メールが届く（件名・本文がいつもどおり）
   - [ ] 申請データに **新しい行** が増える（上書きではない）
   - [ ] C列（タスク種別）が **`新規投稿`**
   - [ ] リストチェックに対象者側で見える（自分宛なら自分の一覧）

## B. 再投稿

1. ホーム → **再投稿** → 期限切れの過去依頼を選ぶ → **再投稿する**
2. 期限だけ選び直して送信（宛先は引き継ぎ）
3. 確認
   - [ ] 申請データに **新しい行** が増える
   - [ ] C列が **`再投稿`**
   - [ ] 宛先が「元と同じ想定」になっている（大きく欠けていない）
   - [ ] メールが新規依頼と同様に届く

## C. リマインド

1. ホーム → **リマインド** → 期限切れの過去依頼 → **リマインドする**
2. 未実施者だけが宛先になっていることを確認し、期限を選び直して送信
3. 確認
   - [ ] 申請データに **新しい行** が増える（元の行は残る）
   - [ ] C列が **`リマインド`**
   - [ ] 宛先が **未実施者寄り**（完了済みだけの人に送っていない）
   - [ ] admin で当該行のバッジが「リマインド」と分かる

## D. admin（任意・1分）

1. 進捗管理admin を開く
2. **投稿の種類** で「すべて / 新規投稿 / 再投稿 / リマインド」を切り替える
3. 確認
   - [ ] 「すべて」で一覧が出る
   - [ ] 「リマインド」だけにすると、C列がリマインドのものが残る

---

## やってはいけないこと（このチェックの範囲外）

- 申請データの既存行の ID・完了データの手直し（検証以外）
- 本番の大量宛先へのテスト送信

問題が出た場合：該当デプロイを戻す／直前の GAS ファイルに戻す。シートの「申請データ」は原則ロールバックしない（行追加型のため、テスト行の削除で足りることが多い）。
